Important correction to the Query expiration/share logic: A Query has its own scheduled expiration. Sharing/opening the Query does NOT stop, pause, reset, extend, or alter that expiration timeline. The share state is only an access state. CORE RULE Query expiration clock = tied to the Query record and tier rules. Share/open state = whether the Query is accessible through its share URL. These must remain completely independent. DO NOT: * pause expiration when shared * reset expiration when shared * extend expiration when shared * hide expiration when shared * replace expiration with shared status DO: * continue showing the Query expiration countdown whether the Query is shared or private * show shared/open state separately * allow the Query to expire on schedule even if it is shared DESIRED SIDEBAR STATUS LINE Shared + expiring: SHARED · 89 DAYS LEFT Private + expiring: 89 DAYS LEFT Shared + expires soon: SHARED · 3 DAYS LEFT Private + non-expiring: NON-EXPIRING Shared + non-expiring: SHARED · NON-EXPIRING Expired: EXPIRED Shared + expired: SHARED · EXPIRED DATA LOGIC Expiration should be calculated from the Query’s own expiration fields/tier logic. Example conceptual fields: * query.createdAt * query.expiresAt * query.archiveDays * query.tier * query.isNonExpiring Shared state should be calculated separately. Example conceptual fields: * query.isOpen * query.shared * _openThreadIds.has(query.id) Do not mix these concerns. DISPLAY LOGIC Build the sidebar status line like this: const expirationLabel = getQueryExpirationLabel(query); const sharedLabel = isQueryShared(query) ? "SHARED" : ""; const statusLine = sharedLabel ? `${sharedLabel} · ${expirationLabel}` : expirationLabel; IMPORTANT getQueryExpirationLabel(query) should not care whether the Query is shared. isQueryShared(query) should not care when the Query expires. FINAL PRINCIPLE Sharing opens access. Expiration governs retention. One does not control the other.
